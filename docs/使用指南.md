# CancelProof 中文指南

这是面向可信本地 asyncio 测试场景的源码实验版。通过显式命名检查点调用真实 `Task.cancel()`，在框架清理前检查用户声明的资源与业务条件。每次运行使用独立子进程，父进程设置截止时间。

Windows 使用 README 中的虚拟环境命令，Linux 将解释器换为 `.venv/bin/python`。不需要云服务。运行 `python -m cancelproof examples` 查看样例。先运行正常基线，再指定 `examples/plans/lock.json` 比较 `lock_broken` 与 `lock_fixed`；退出码 2 是故障被检出，不是工具安装失败。

输出目录必须尚不存在，目录中有 report.json、report.html、report.md、replay.json。HTML 可直接本地打开，无脚本和外部资源。具体步骤、任务逻辑名称、实际取消请求、断言和版本记录在 JSON 中。重放只校验场景模块哈希，不涵盖其依赖和外部环境。

在自己的模块定义 `async def scenario(probe)`，用 `probe.create_task` 或 `probe.track` 注册任务，用 `invariant` 定义准确的同步布尔判断。文件/会话关闭、令牌计数、余额守恒、取消后不得提交均需要用户声明，工具不会猜测业务规则。合法长期后台任务通过 `allow_background` 明确排除；未分类 pending 只返回 INCONCLUSIVE。正常取消本身不等于缺陷。

PASS 仅证明本次已执行的条件通过；FAIL 是观察到的断言/运行错误；INCONCLUSIVE 表示未到达检查点、信息不完整或超时等；NOT_RUN 表示没有执行目标。不同于判决的 outcome 独立记录正常完成、取消、异常和超时。

不能控制任意 await、Python 字节码、系统调度，也不证明没有竞态。`explore` 仅从基线可达检查点选择有界取消方案，seed 改变选择顺序。只运行可信代码：导入和执行都使用当前权限，子进程不是恶意代码沙箱。Windows/Linux 都没有硬内存配额，不能保证回收目标自行创建的后代进程。主动分享的事件值仍可能包含敏感信息，请先检查再分享报告。

ASGI 样例使用真实 HTTPX ASGITransport 请求和真实服务逻辑，但没有公网监听、ASGI lifespan、生产负载或网络故障验证。完整环境记录、竞品重叠、历史问题复现和未完成项见最终报告。项目不宣称科研创新。
