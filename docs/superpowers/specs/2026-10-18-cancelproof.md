# CancelProof bounded cancellation contract

User authorizes autonomous design/implementation/review without intermediate approval, explicitly local-only. This specification chooses among three approaches: direct in-process pytest helpers (simple but cancellation-resistant cleanup can hang the harness), a custom deterministic asyncio scheduler (unnecessary reinvention and broad unsupported guarantees), or named checkpoints plus ordinary asyncio in independently bounded child processes. Choose the third; retain direct Task.cancel + pytest/pyleak as serious baselines rather than claiming unique fault injection.

## Public API and execution boundary

Python3.12/3.13, standard asyncio public APIs only. Trusted scenario is an importable `module:async_callable`, signature `async def scenario(probe)`. No arbitrary source eval, bytecode/await instrumentation, malicious-code sandbox, or remote service. All code imports execute trusted local code and may have side effects. Each run starts a fresh Python subprocess/event loop. The synchronous Python API and CLI have a hard parent deadline; async API polls the same child with a finally cleanup, preserving caller task identity. Descendant processes/native resources are not OS-sandboxed.

`run_scenario(scenario, plan=None, limits=None) -> dict`, `await arun_scenario(...) -> dict`, `campaign(scenario, max_runs=12, seed=0, repeats=1, limits=None) -> dict`. No import execution in CLI argument parsing. A missing/unreached action is NOT_RUN at action level and INCONCLUSIVE overall, never silently PASS. `campaign` discovers reached checkpoints in an uncancelled baseline, then injects one action per selected occurrence/task, optionally repeats; it is bounded coverage, not exhaustive interleavings. Seed changes chosen plan order/delays, not arbitrary event-loop scheduling.

Plan JSON keys: `actions` list (max32), `expected` dict label->`completed|cancelled` (max64). Each action has `checkpoint` nonempty <=128 chars, `task` optional logical target label (default checkpoint caller), `occurrence` positive int<=1000 (counted per caller label/name), `repeat` int1..4, `delay_turns` int0..10. Actions trigger real `Task.cancel()`; no explicit raise CancelledError. At a checkpoint a zero-delay first cancellation is immediate; delayed/repeated requests run on a harness controller task with logged delivery/accepted results. Ordinary ready-queue scheduling remains uncontrolled. Engine-created tasks are never user cancellation targets.

Limits JSON: `timeout` soft scenario seconds0.05..30(default1), `grace` seconds0.01..5(default0.15), `wall_timeout` seconds0.2..60(default5), `max_tasks`1..128(default32), `max_events`16..10000(default2000). Wall timeout must allow soft timeout+grace+startup margin. External campaign total <=120s, max_runs1..64, repeats1..8, global64 cases. Worker report/request/log caps and parent process cleanup ensure bounded delivery, not a memory or malicious-process sandbox.

## Probe interface

- `await probe.checkpoint(name)`: log logical caller/name/occurrence, schedule matching real cancellations and yield via asyncio.sleep(0).
- `probe.create_task(coro, name, must_finish=True)` and `probe.track(task, name, must_finish=True)`: explicit related-task registry, no CPython private fields. Root label `scenario`. `probe.allow_background(task, reason)` explicitly exempts a tracked/new background task from finish-at-boundary contract but its state and later harness cleanup remain reported. Duplicate names/task-count violations are errors.
- `probe.invariant(name, predicate, *, category='business', actual=None, expected=True)`: synchronous post-run predicates; exact bool result. Predicate exception/nonbool/awaitable ->INCONCLUSIVE, not PASS. Optional actual callable supplies user-approved JSON evidence, not frame-local dumping. `probe.watch_lock(name, lock)` uses public locked(). File/session cleanup via custom `.closed` predicate; capacity via user counter/queue ledger, no semaphore._value.
- `probe.event(name, **details)` records caller-supplied cleanup/commit events, bounded JSON only. `probe.observe(name,value)` records explicit state. User data may be sensitive; reports default to no exception messages/frame locals or full local paths. `probe.expect_cancelled(name)` enforces propagation only when an injection actually requests cancellation of that logical task. `probe.require_no_pending()` declares all new nonexempt application tasks must have ended at boundary; otherwise unregistered pending tasks are INCONCLUSIVE candidates, not automatic leak proof.

## Judgments and cleanup

Separate `verdict=PASS|FAIL|INCONCLUSIVE|NOT_RUN` from `outcome=completed|cancelled|exception|timeout|hard_timeout|not_run`. Ordinary expected CancelledError is not a bug. Invariant false, unexpected task exception, declared propagation/finish contract violation ->FAIL. Unsupported observation/evaluation, unreached injection, unclassified pending task, or hard deadline without reliable final state ->INCONCLUSIVE. The soft deadline requests actual cancel, records its cause and waits a bounded grace; it is not the fault-plan action. Root remains pending at boundary is timeout evidence, not proof of an infinite deadlock. Parent cannot declare PASS until child exited cleanly; a hung asyncio.run shutdown becomes hard_timeout/INCONCLUSIVE even if a provisional report existed.

At the observation boundary, record task states/invariants/events BEFORE harness cleanup so cleanup cannot hide a defect. Then request cancellation only of tasks created in this run (excluding engine/root/controller identities); settle boundedly and record residuals. Exempt long-lived tasks are not called leaks, but isolated process must still clean/exit or return INCONCLUSIVE. No blanket cancellation of another caller/event-loop baseline. Exceptions record type and basename/line/function only; user explicitly shared values remain evidence. Process-kill recovery preserves bounded flushed event JSONL, outcome/reason, not invented invariant results.

## Report and interface contract

Run dict contains schema_version=1, version, scenario, verdict, outcome, plan, limits, environment, source_sha256 (when available), actions (requested/hit/deliveries), checkpoints, events, tasks, invariants, diagnostics, cleanup and limitations. JSON-compatible; no exception objects or raw source. Evidence uses event sequence indexes/relative trace paths. Replay records scenario+plan+limits+source digest; source mismatch is disclosed and cannot claim exact controlled replay.

Aggregate dict contains schema_version=1, version, scenario, verdict, runs, selection (mode/seed/repeats/bounded limits), summary and limitations. CLI `run`, `explore`, `replay`, `examples`; trusted local importable target explicit. Run accepts --plan JSON and --limits JSON; explore --max-runs --seed --repeats. --output NEWDIR writes report.json/report.html/report.md plus replay.json. stdout machine JSON, stderr concise status/errors. Exit0 PASS,2 FAIL,3 INCONCLUSIVE/NOT_RUN,1 invalid input/target/config (argparse syntax2). No overwrite. HTML inert escaped, no remote assets/JavaScript. Markdown escapes injected HTML/fences. pytest plugin provides reusable fixture `cancelproof` returning the run_scenario callable and `cancelproof_async` returning arun_scenario; no global event loop changes.

## Acceptance and claims

Literal broken/fixed examples: lock after acquisition; queue capacity tokens with concurrent workers; swallowed cancellation with explicit propagation contract; pending owned background request task; repeated cancellation during async cleanup; TaskGroup normal/exception/cancel behavior; actual HTTPX ASGITransport requests to a complete small ASGI service. Correct implementations must pass specified plans; broken ones must fail their declared invariants. Hard-hanging/sync-blocking and caller-cancel tests must terminate child and return/propagate boundedly. Missing checkpoint and intentional/excluded background controls must avoid false bugs.

Keep full original logs, fixed history sources/versions, baseline commands, failures, environment and independent review outside public source; include only generated safe cases/selected evidence in distribution. All test dependencies reviewed/pinned source+wheelhash+license+time. Core runtime stdlib only; pytest and HTTPX optional test/demo dependencies. New independent directory/local Git only. No GitHub repo/push/PR/Release. No scientific novelty, exhaustive race-freedom, real-world false-positive rate or malicious-code isolation claim. Final four-way readiness may be NO-GO if fair baselines establish no incremental value.
